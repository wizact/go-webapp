# Agent Guide — go-webapp

## Overview

This is a Go web application that uses the **Echo** web framework, **Templ** for server-side HTML templating, **HTMX** for dynamic interactions, **Tailwind CSS** for styling, and **Vite** for bundling TypeScript/CSS assets. It follows a hybrid architecture: Go handles routing and server-side rendering while Vite manages the frontend asset pipeline.

## Repository Structure

```
.
├── main.go                # Application entry point (routes, server lifecycle)
├── static_dev.go          # Dev-mode static asset middleware (build tag: dev)
├── static_prod.go         # Prod-mode static asset middleware (embed.FS, build tag: !dev)
├── Makefile               # Build and live-reload commands
├── .air.toml              # Air live-reload configuration for Go
├── go.mod / go.sum        # Go module dependencies
├── package.json           # Node.js dev dependencies (Vite, Tailwind, PostCSS)
├── vite.config.ts         # Vite build configuration
├── tailwind.config.js     # Tailwind CSS content paths
├── postcss.config.js      # PostCSS plugins (import, nesting, tailwind, autoprefixer)
├── tsconfig.json          # TypeScript compiler options
├── views/                 # All view-layer source files
│   ├── layouts/           # Templ base layout(s)
│   ├── components/        # Reusable Templ UI components
│   ├── pages/             # Page-level Templ templates (one subdir per page)
│   ├── css/               # Source CSS (Tailwind entry point)
│   └── scripts/           # TypeScript source and module system
│       ├── index.ts       # Dev entry: auto-loads modules via data-module attributes
│       ├── module-loader.ts # Prod entry: manifest-based module loader
│       └── modules/       # Individual TS modules loaded on demand
├── assets/                # Vite build output (JS, CSS, manifest)
├── public/                # Public static files (favicon, etc.)
└── out/                   # Production build output (binary + embedded assets)
```

## Structural Patterns

### 1. Build-Tag Conditional Compilation

The application uses Go build tags to switch behavior between development and production:

- **`static_dev.go`** (`//go:build dev`): Serves assets from the local `assets/` directory on disk. Used during `make live` via Air.
- **`static_prod.go`** (`//go:build !dev`): Embeds the `assets/` directory into the binary with `//go:embed` and serves via `embed.FS`. Used for the production build (`go build -tags 'prod'`).

When adding new build-mode-specific behavior, follow this same pattern: create paired files with complementary build tags.

### 2. Templ Component Hierarchy

Templates use the [Templ](https://templ.guide/) library and follow a three-tier hierarchy:

- **Layouts** (`views/layouts/`): Define the full HTML document shell (head, body, scripts, stylesheets). The `Base` layout accepts `children` via `{ children... }`.
- **Components** (`views/components/`): Reusable UI fragments (Header, Footer, Navigation). Imported and composed inside layouts.
- **Pages** (`views/pages/<name>/`): Each page lives in its own subdirectory and package. A page template wraps its content inside `@layouts.Base(name) { ... }`.

**Conventions:**
- Each `.templ` file has a corresponding generated `_templ.go` file (auto-generated by `templ generate`). Never edit `_templ.go` files by hand.
- Page packages are named after the page (e.g., `package home`, `package about`, `package product`).
- Templ components are imported and called with the `@` syntax.

### 3. Echo Routing Pattern

Routes are defined in `main.go` as inline handler functions on the Echo instance:

```go
e.GET("/path", func(c echo.Context) error {
    component := <package>.<TemplFunc>(args)
    return Render(c, http.StatusOK, component)
})
```

The `Render` helper bridges Echo and Templ by rendering a `templ.Component` into the Echo response. When adding new pages, follow this pattern: create the Templ page, then register a GET route in `main.go` that renders it.

### 4. Asset Pipeline (Vite + Tailwind)

- **Tailwind CSS**: Source is `views/css/global.css` → output is `assets/styles/global.css`. Content scanning includes `.html` and `.templ` files.
- **Vite**: Bundles TypeScript from `views/scripts/` → output goes to `assets/`. Two entry points are configured: `index.ts` and `module-loader.ts`.
- **PostCSS**: Configured with `postcss-import`, `postcss-nesting`, `tailwindcss`, and `autoprefixer`.

Assets are served under the `/assets` route group, which uses the build-tag middleware described above.

### 5. Dynamic Module Loading (data-module)

The frontend uses a convention-based module loading system:

- HTML elements with a `data-module="<name>"` attribute trigger automatic loading of the corresponding TypeScript module from `views/scripts/modules/<name>.ts`.
- **Dev mode** (`index.ts`): Uses Vite's `import.meta.glob` for dynamic imports.
- **Prod mode** (`module-loader.ts`): Reads the Vite manifest (`assets/.vite/manifest.json`) to resolve and load module files.

When adding new client-side behavior to a component, create a new `.ts` file in `views/scripts/modules/` and add `data-module="<name>"` to the relevant HTML element in the Templ template.

### 6. Graceful Server Shutdown

`main.go` implements graceful shutdown: it listens for `SIGTERM`/`SIGINT`, then calls `e.Shutdown(ctx)` with a 6-second timeout. This pattern ensures in-flight requests complete before the process exits.

### 7. Structured Logging

The application uses Go's `log/slog` package with a JSON handler (`slog.NewJSONHandler`). Use `logger.Info(...)` and `logger.Error(...)` for application-level logging.

## Development Commands

| Command | Description |
|---|---|
| `make live` | Start full dev environment with HMR (runs templ, air, tailwind, vite, and sync in parallel) |
| `make build` | Production build: generates templ, minifies CSS, bundles JS, compiles Go binary to `out/` |
| `templ generate` | Regenerate `_templ.go` files from `.templ` sources |

## Adding a New Page (Checklist)

1. Create a new directory under `views/pages/<name>/`.
2. Add a `.templ` file in the new directory. Use a dedicated package name. Import and wrap content with `@layouts.Base(name) { ... }`.
3. Run `templ generate` to produce the `_templ.go` file.
4. Add a route in `main.go` following the existing `e.GET(...)` / `Render(...)` pattern.
5. If the page needs client-side JS, add a module in `views/scripts/modules/` and reference it via `data-module` on an HTML element.
6. Add a navigation link in `views/components/navigation.templ` if needed.
